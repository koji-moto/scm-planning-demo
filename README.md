# Stockscape — 超小型需給計画システム

食品メーカーの需給計画の基本を、架空の冷凍食品3商品で学ぶためのブラウザアプリです。実在する会社・商品・顧客の情報、外部API、データベースは使用していません。

## このシステムがしていること

- 商品ごとに8週間の**販売計画・製造計画・週末在庫**を一覧表示します。
- 製造計画の白い入力欄を変更すると、その週以降の在庫とグラフを即座に再計算します。
- 週末在庫が安全在庫未満なら黄色、0未満なら赤色の「欠品」で知らせます。
- 選択中の商品について、週末在庫と安全在庫を折れ線グラフで比較できます。

入力内容はブラウザを再読み込みすると初期値に戻ります。学習用のため、データ保存や需要予測、最適化は行いません。

## 在庫計算の考え方

各週を左から順に、次の式で計算します。

```text
週末在庫 = 前週末在庫 + 製造計画 - 販売計画
```

1週目だけは「前週末在庫」がないため、商品の**現在庫**を使います。たとえば現在庫100個、1週目の製造30個、販売40個なら、週末在庫は `100 + 30 - 40 = 90個` です。2週目はこの90個を出発点にします。そのため、ある週の製造計画を変えると、その週だけでなく後の週もすべて変わります。

## 各ファイルの役割

| ファイル | 役割 |
| --- | --- |
| `index.html` | 見出し、商品タブ、計画表、グラフなど画面の骨組み |
| `styles.css` | 色、余白、表、警告表示、スマートフォン対応などの見た目 |
| `inventory.js` | 架空の商品データ、在庫計算、警告判定（中心となるロジック） |
| `app.js` | 入力操作の受け取り、表の更新、集計、グラフ描画 |
| `test/inventory.test.js` | 在庫計算と警告判定が正しいかを自動確認するテスト |
| `package.json` | 起動・テスト用コマンドの定義 |

## 動かし方

必要なものは **Python 3** と、テストをする場合は **Node.js 18以上**です。追加パッケージのインストールは不要です。

1. ターミナルでこのフォルダーへ移動します。
2. 次のコマンドで簡易Webサーバーを起動します。

   ```bash
   npm start
   ```

3. ブラウザで <http://localhost:8000> を開きます。
4. 商品タブを選び、「製造計画」の白い数字を変更して在庫の変化を確認します。
5. 終了するときはターミナルで `Ctrl + C` を押します。

`index.html` を直接ダブルクリックせず、上記のサーバー経由で開いてください。JavaScriptのモジュールを正しく読み込むためです。

## ChromebookからGitHub Pagesで確認する方法（Linux不要）

このアプリは、GitHub Pagesでそのまま公開できます。ChromebookのLinux環境、ターミナル、追加アプリは使いません。必要なのはChromeとGitHubアカウントだけです。

> **公開前の確認：** GitHub Pagesはリポジトリに保存された内容をWebサイトとして公開します。このアプリの初期データはすべて架空ですが、自分で実在する商品・顧客などの情報を追加した場合は公開しないでください。

### 1. アプリの変更をメインブランチへ反映する

1. Chromeで、このリポジトリのGitHubページを開きます。
2. ページ上部の **Pull requests** をクリックします。
3. このアプリを追加したPull Requestをクリックします。
4. 緑色の **Merge pull request** をクリックします。
5. 続けて **Confirm merge** をクリックします。
6. ページ上部の **Code** をクリックしてリポジトリへ戻ります。
7. ファイル一覧に `index.html`、`app.js`、`inventory.js`、`styles.css` があることを確認します。

すでにPull Requestがマージ済みで、ファイルが表示されている場合は手順2～5を飛ばしてください。**Merge pull request** が表示されない場合は、そのリポジトリの管理者にマージを依頼します。

### 2. GitHub Pagesを有効にする

1. リポジトリ上部の **Settings** をクリックします。
2. 左側メニューの **Code and automation** 欄にある **Pages** をクリックします。
3. **Build and deployment** 欄の **Source** で **Deploy from a branch** を選びます。
4. **Branch** の左側で、アプリが入っているメインブランチ（通常は `main`）を選びます。
5. 右側のフォルダー選択で **/ (root)** を選びます。
6. **Save** をクリックします。

**Settings** が表示されない場合は、このリポジトリを設定する権限がありません。自分のアカウントへリポジトリを **Fork** して、フォーク先で同じ操作をするか、リポジトリの管理者に設定を依頼してください。

### 3. 公開の完了を待つ

1. **Save** の後、そのまま1～5分ほど待ちます。
2. 必要に応じてページを再読み込みします。
3. Pages設定画面の上部に **Your site is live at ...** と公開URLが表示されたら完了です。
4. **Visit site** をクリックします。

通常、公開URLは次の形になります。

```text
https://GitHubのユーザー名.github.io/scm-planning-demo/
```

公開処理の状況は、リポジトリ上部の **Actions** を開き、`pages build and deployment` を選ぶと確認できます。緑色のチェックが付けば成功です。

### 4. アプリを操作して確認する

公開された画面で、次の順に試します。

1. `冷凍パスタA`、`冷凍うどんB`、`冷凍ラーメンC` のタブを順番にクリックします。
2. 「製造計画」にある白い入力欄の数字を変更します。
3. 変更した週以降の「週末在庫」が自動的に変わることを確認します。
4. 安全在庫未満が黄色、0未満が赤色の「欠品」になることを確認します。
5. 画面下部の在庫推移グラフも同時に変わることを確認します。

入力した数字は保存されません。ページを再読み込みすると、最初の架空データに戻ります。

### 公開できないとき

- **404ページが表示される：** 保存直後はまだ公開処理中のことがあります。数分待ち、Pages設定画面に表示されたURLから開き直します。
- **公開URLが表示されない：** **Settings** → **Pages** で、ブランチが `main`、フォルダーが **/ (root)** になっているか確認します。
- **`main` を選べない：** Pull Requestがまだマージされていない、またはメインブランチの名前が別名です。`index.html` が存在するブランチを選びます。
- **Actionsに赤い×が付く：** 赤い×をクリックしてエラー内容を確認し、リポジトリの管理者へ画面の内容を伝えます。
- **SettingsやPagesがない：** リポジトリの管理権限、組織の設定、または利用プランによって公開できないことがあります。管理者へ確認するか、自分の公開リポジトリへForkします。

詳しい公式手順は、GitHub Docsの[GitHub Pagesサイトの作成](https://docs.github.com/ja/pages/getting-started-with-github-pages/creating-a-github-pages-site)でも確認できます。
